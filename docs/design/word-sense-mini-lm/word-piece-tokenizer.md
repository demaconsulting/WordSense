# WordPieceTokenizer Unit Design

## Overview

`WordPieceTokenizer` reproduces the BERT uncased tokenizer used by `all-MiniLM-L6-v2`: Unicode
normalization (NFD, accents stripped, lower-casing), splitting on whitespace and punctuation, CJK
characters as separate words, and greedy longest-match WordPiece with `##` continuations. A word of more
than 100 normalized characters (code points after accent stripping), or with no match, becomes one `[UNK]`
spanning the whole word.

## Data Model

- `TokenizedText`: parallel arrays of token ids and UTF-16 start/end offsets into the original text
  (special tokens are not included).
- `TokenizedText.WordFirst` / `WordEnd`: for each word, the index range of its tokens (first token and one past
  the last); both are empty unless the result was produced by `TokenizeWords`.
- The vocabulary is a dictionary from piece to id, loaded from `vocab.txt` (line number is the id).

## Methods

- `WordPieceTokenizer(IEnumerable<string>)` / `FromFile(path)`: build from a vocabulary.
- `Tokenize(text)`: returns the tokens with offsets mapped back to the original text, including
  surrogate pairs and characters that normalization changes in length.
- `TokenizeWords(words)`: tokenizes each word separately and returns the pieces with the piece range of
  every word; the text offsets are those of the words joined by single spaces.
- `UnknownId`, `ClsId`, `SepId`: the vocabulary ids of `[UNK]`, `[CLS]` and `[SEP]`.
- `TokenizedText.BuildWindow(clsId, sepId, maxLength, targetFirst, targetEnd)`: model input ids framed
  by `[CLS]` and `[SEP]` that fit `maxLength` ids and keep the target tokens inside; returns the ids and
  the target range within the window, clipped to the window when the target is longer than its capacity.
  `maxLength` must be at least 8; the unit does not check this because the only caller,
  `MiniLMWordSenseModel`, validates its `maxSequenceLength` (8 to 512) before building a window, and a
  smaller value is a programming error.

## Error Handling

- `ArgumentNullException` for a null vocabulary, text, word list, or word in the list.
- `ArgumentException` when the vocabulary lacks `[UNK]`, `[CLS]` or `[SEP]`.
- `IOException` (or a derived exception) from `FromFile` when the vocabulary file cannot be read.
- Characters that BERT text cleaning removes never raise an exception: NUL, U+FFFD, lone surrogates, and every
  code point of the Unicode categories control (other than tab, line feed and carriage return), format,
  unassigned, private-use and surrogate are dropped. Other white space becomes a space.

## Interactions

Used by `MiniLMWordSenseModel` and by `WordSenseBuilder` (through the internals-visible declaration of the MiniLM
assembly). It has no dependencies on other units. The classifier of the core package does not use it. The tokenizer is
internal to the MiniLM package.
Parity with the reference tokenizer is established by a fixture of 176 cases generated by the Hugging
Face `tokenizers` package (`tools/tokenizer-fixture`).
